# Local RAG Governance Demo Walkthrough

This walkthrough explains the local Python RAG flow in this example.
It uses synthetic markdown, deterministic JSON outputs, and simple local scoring so the workflow can be reviewed without cloud access or model calls.

## What This Demo Shows

The demo shows how a governed RAG workflow can produce evidence before any provider-hosted retrieval, vector index, or LLM evaluation service is introduced.

It demonstrates:

- local document ingest and chunking
- governance-aligned chunk metadata
- evaluation (eval) dataset preparation
- synthetic response scoring
- a TypeScript mock RAG query endpoint that returns governed response evidence
- deterministic sample outputs for review

## End-to-End Flow

```text
synthetic markdown docs
  -> local ingest and chunking
  -> governance-aligned chunk JSON
  -> local eval dataset JSON
  -> synthetic mock responses
  -> deterministic score report
  -> mock governed RAG API response
```

## Step 1: Source Documents

The source document is:

- `examples/rag-pattern/python/sample_docs/cloudai-demo-handbook.md`

It is synthetic demo content. The document describes governance signals, metadata, citation expectations, and operational evidence in generic CloudAI platform terms.

## Step 2: Chunk Export

The chunk export is:

- `examples/rag-pattern/python/sample_outputs/cloudai-rag-chunks.json`

This file represents the local ingest artifact. It includes fields that are useful for future retrieval and governance evidence:

- `sourceId`
- `sourceTitle`
- `citationUrl`
- `classification`
- `retrievedAt`
- `chunkId`
- `chunkIndex`
- `metadata`
- `text`

This is not a retrieval runtime or a vector index. It is a deterministic local representation of what future retrieval infrastructure would need to preserve.

## Step 3: Eval Dataset

The eval dataset is:

- `examples/rag-pattern/python/sample_outputs/cloudai-rag-eval-dataset.json`

Each eval case describes what a future answer should be checked against:

- the question
- the expected source
- whether a citation is required
- the source chunk used as evidence
- quality notes for review

This prepares evaluation evidence without calling an LLM or external scoring service.

## Step 4: Mock Responses

The mock response set is:

- `examples/rag-pattern/python/sample_outputs/mock-rag-responses.json`

These responses are synthetic examples used to exercise the local scoring harness.
They are not generated by a model and do not represent a deployed application.

## Step 5: Score Report

The score report is:

- `examples/rag-pattern/python/sample_outputs/cloudai-rag-score-report.json`

The local scoring harness checks:

- response present
- expected source present
- citation requirement met
- unsupported marker absent

The score report is intentionally simple. It demonstrates the structure of response-quality evidence before model-based evaluation is added.

## Step 6: Mock Governed RAG Query

The TypeScript mock API exposes:

- `POST /rag/query`

It accepts the governed RAG request fixture:

- `shared/examples/rag-governance/rag-request.allowed.json`

It returns a deterministic synthetic governed response with:

- citation metadata
- retrieval metadata
- egress decision
- audit evidence
- no query text echo in the response body

This endpoint does not perform retrieval, execute Python, call a model, create embeddings, or use a vector index. It demonstrates the API control point that a future provider-backed RAG implementation could preserve.

## Run The Demo Locally

From the repository root, run:

```bash
PYTHONPATH=examples/rag-pattern/python python3 -m unittest discover -s examples/rag-pattern/python/tests
```

To regenerate the three output artifacts locally:

```bash
PYTHONPATH=examples/rag-pattern/python python3 -m rag_ingest.cli \
  --docs examples/rag-pattern/python/sample_docs \
  --out /tmp/cloudai-rag-chunks.json \
  --knowledge-base cloudai-demo-handbook

PYTHONPATH=examples/rag-pattern/python python3 -m rag_ingest.cli \
  --mode eval-dataset \
  --docs examples/rag-pattern/python/sample_docs \
  --out /tmp/cloudai-rag-eval-dataset.json \
  --knowledge-base cloudai-demo-handbook \
  --dataset-id cloudai-rag-eval-demo

PYTHONPATH=examples/rag-pattern/python python3 -m rag_ingest.cli \
  --mode score-report \
  --eval-dataset /tmp/cloudai-rag-eval-dataset.json \
  --responses examples/rag-pattern/python/sample_outputs/mock-rag-responses.json \
  --out /tmp/cloudai-rag-score-report.json
```

The commands write local outputs under `/tmp` and do not create cloud resources.

To run the mock RAG query endpoint manually, start the API:

```bash
cd providers/aws/app/api
pnpm run dev
```

From the repository root in another terminal:

```bash
curl -s http://localhost:3000/rag/query \
  -H "content-type: application/json" \
  -d @shared/examples/rag-governance/rag-request.allowed.json
```
